# DefenceAll

히어로를 모으고 성장시키는 **2D 픽셀아트 디펜스 게임**. 2인 개발 프로젝트입니다.

## 현재 상태

**기획(명세) 단계**입니다. 1단계 프로토타입의 범위를 정하는 중이며, 아직 게임 코드는 없습니다.

## 게임 개요 (기획 기준)

- **히어로가 게임의 중심**입니다. 히어로 **1명으로 시작**하고, 진행하면서 슬롯이 해금되어 최대 **3인 스쿼드**로 싸웁니다.
- 기본 히어로 1종을 제공하고, 추가 히어로는 **가챠(뽑기)** 로 획득합니다.
- 히어로는 총 **73종**입니다. 등급은 신화 1 / 전설 4 / 영웅 8 / 희귀 15 / 고급 20 / 일반 25종이고, 클래스는 탱커 · 광역 딜러 · 단일 딜러 · 서포터 4종입니다.
- 스쿼드는 하나의 **통합 HP**를 공유하는 구조를 기준으로 기획하고 있습니다. (확정 필요)
- 엔진은 **Unity**, 그래픽은 **2D 픽셀아트**입니다.

## 개발 방식: 명세 주도 개발 (SDD)

코드를 짜기 전에 명세를 먼저 쓰고, 합의한 명세를 기준으로 구현합니다.

1. **명세 작성**: 동작, 수치, 예외 상황, 완료 조건, 범위 밖을 문서로 적는다.
2. **명세 검토**: Pull Request로 올리고 상대방이 확인한 뒤 merge한다.
3. **구현**: 합의된 명세대로 Unity에서 만든다.
4. **검증**: 명세의 완료 조건을 하나씩 확인한다.
5. **명세 갱신**: 구현 중 바뀐 내용은 코드보다 먼저 명세를 고친다.

## 결정된 것과 미정인 것

**결정**
- Unity, 2D 픽셀아트
- 명세 주도 개발(SDD)
- 히어로 1명으로 시작해 슬롯 해금으로 최대 3명
- 추가 히어로는 가챠로 획득

**미정**
- 히어로와 디펜스(타워 등)의 관계, 전투 조작 방식
- 스쿼드 통합 HP 구조 확정
- 캐릭터 스프라이트 해상도, 시작 히어로 선택
- 슬롯 해금 조건, 중복 히어로와 승급 처리
- 결제 연동 여부 (연동 시 확률 정보 공개 등 법적 요건 확인 필요)
- Unity 에디터 버전 (팀원 모두 같은 버전을 써야 함)

## 협업 규칙 (안)

- `main`에 직접 push하지 않고, 작업 브랜치에서 작업한 뒤 Pull Request로 합칩니다.
- 명세를 바꿀 때도 Pull Request로 올려 서로 확인합니다.
- 작업을 시작하기 전에 항상 최신 상태를 받습니다. (Fetch origin, Pull origin)
- 같은 씬이나 프리팹을 동시에 수정하지 않습니다. 담당을 미리 나눕니다.
- 팀원 모두 같은 Unity 에디터 버전을 사용합니다.
