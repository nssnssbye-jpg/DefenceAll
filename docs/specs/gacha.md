# 가챠(뽑기) 명세

- 상태: 초안 (검토 전)
- 관련 문서: [hero.md](hero.md)
- 표기: `(미정)`은 아직 결정하지 않은 항목, `(안)`은 임시 제안값

## 1. 목적

플레이어가 재화를 사용해 새 히어로를 획득하는 시스템이다. 수집과 성장의 동기를 만든다.

## 2. 동작 설명

- 플레이어는 뽑기 재화를 소모해 **1회 뽑기** 또는 **10회 뽑기**를 실행한다.
- 결과로 히어로 1종 또는 10종이 지급되고, 보유 목록에 추가된다.
- 결과 연출 후 획득한 히어로를 확인할 수 있다.

## 3. 재화

| 재화 | 용도 | 획득 경로 |
|---|---|---|
| 뽑기 재화 (이름 미정) | 뽑기 실행 | 스테이지 클리어 보상, 일일 보상 (안) |

- 1회 비용, 10회 비용 (미정)
- 실제 결제(현금) 연동 여부 (미정, 아래 열린 질문 참고)

## 4. 확률표 (안)

아래 수치는 예시이며, 밸런스 논의 후 확정한다.

| 등급 | 확률 |
|---|---|
| 일반 | 45% |
| 고급 | 30% |
| 희귀 | 15% |
| 영웅 | 8% |
| 전설 | 1.8% |
| 신화 | 0.2% |

- 합계는 항상 100%가 되어야 한다.
- 같은 등급 안에서는 각 히어로가 동일한 확률로 나온다. (안) 예: 신화 0.2%는 1종이므로 그 히어로의 확률이 0.2%이다.

## 5. 보정 규칙

- **천장(Pity)**: 일정 횟수 동안 최고 등급이 나오지 않으면 다음 뽑기에서 확정 지급 (미정: 횟수)
- **10회 뽑기 보장**: 희귀 이상 1종 이상 확정 (안)
- 천장 카운트는 저장되어 게임을 종료해도 유지된다.

## 6. 중복 처리

- 이미 보유한 히어로가 나오면 (미정: 조각 변환 / 돌파 재료 / 재화 환급)

## 7. 예외 상황

- 재화가 부족할 때: 뽑기 버튼이 비활성화되고 부족하다는 안내를 표시한다.
- 뽑기 도중 앱이 종료될 때: 재화 차감과 지급이 함께 처리되어야 한다. (차감만 되고 지급이 안 되는 상황 방지)
- 결과 저장 실패 시 처리 (미정)

## 8. 완료 조건

- [ ] 1회 뽑기와 10회 뽑기가 동작한다.
- [ ] 재화가 부족하면 뽑기가 실행되지 않는다.
- [ ] 확률표대로 결과가 나온다. (충분한 횟수로 시뮬레이션해 검증)
- [ ] 천장 카운트가 저장되고 정상 동작한다.
- [ ] 확률 정보를 플레이어가 화면에서 볼 수 있다.

## 9. 범위 밖 (이번에는 하지 않음)

- 픽업(확률 상승) 배너
- 뽑기 이벤트, 기간 한정 히어로
- 교환 상점

## 10. 열린 질문

1. 실제 결제(현금)를 연동하는가, 게임 내 재화만 사용하는가?
   - 결제를 연동하거나 확률형 아이템을 유료로 판매하는 경우, 국내에서는 확률 정보 공개 의무 등 법적 요건이 있을 수 있다. 출시 계획이 있다면 반드시 최신 법령을 확인해야 한다.
2. 뽑기 결과는 어디서 결정하는가? (기기 안에서 / 서버에서)
   - 기기 안에서 처리하면 구현이 쉽지만 조작될 수 있다. 서버에서 처리하면 안전하지만 별도 서버가 필요하다.
3. 뽑기 풀에 기본 히어로도 포함되는가?
4. 천장 횟수와 10회 뽑기 보장 규칙을 어떻게 정하는가?
