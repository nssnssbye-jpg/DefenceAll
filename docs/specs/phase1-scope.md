- 상태: 초안 (검토 전)
- 관련 문서: [hero.md](hero.md), [gacha.md](gacha.md), 히어로 도감 5종([신화·전설·영웅](hero-roster.md), [희귀](hero-roster-rare.md), [고급](hero-roster-advanced.md), [일반](hero-roster-common.md))

## 1. 1단계의 목표

73종 전체를 만들기 전에, **적은 수의 히어로로 전투와 가챠가 재미있는지 먼저 확인한다.**

- 클래스 조합(탱커·딜러·서포터)을 바꿀 때 전투 결과가 체감상 달라지는가
- 가챠(10회 뽑기)를 했을 때 기대감과 만족감의 균형이 맞는가
- 히어로와 스킬 데이터를 코드 수정 없이 추가할 수 있는 구조인가
- **1인 구간**(혼자 싸우는 초반)이 충분히 재미있는가
- 슬롯이 1개에서 3개로 늘어날 때 성장감과 전투 변화가 체감되는가

## 3. 시스템 범위

### 포함

| 분류 | 내용 |
|---|---|
| 전투 | 웨이브 진행, 자동 공격, 사거리 기반 타겟팅, 1~3인 스쿼드(슬롯 해금) |
| 체력 | 스쿼드 통합 HP |
| 히어로 스킬 | 쿨타임 자동 발동 스킬(수동 조작 없음, 안), 패시브(N타마다 발동, 주기 회복, 조건부 피해, 스탯 증감) |
| 상태이상 | 기절, 넉백, 슬로우 (3종만) |
| 버프·디버프 | 공격 속도, 치명타 확률, 최대 체력, 방어력 무시, 받는 피해 감소 |
| 버프 중첩 | 같은 스탯의 버프는 **합연산**으로 통일 (안) |

| 데이터 | 히어로 ScriptableObject, CSV로 일괄 입력 |

### 제외 (2단계 이후)

궁극기, 골드와 경제, 히어로 레벨업, 승급·중복 처리(안: 1단계는 중복 시 알림만), 결제, 서버, 신화 등급, 그 외 상태이상, 지대·설치물, 보스 전용 로직

## 3-1. 슬롯 해금 (안)

- 게임은 **히어로 1명(1슬롯)** 으로 시작하고, 진행하면서 슬롯이 열려 **최대 3슬롯**까지 늘어난다.
- 1인 구간에서 통합 HP는 그 히어로 자신의 HP와 같다.

| 시점 | 슬롯 | 비고 |
|---|---|---|
| 시작 ~ 스테이지 2 | 1슬롯 | 기본 히어로 1종으로 진행 |
| 스테이지 3 | 2슬롯 | 스테이지 2 클리어로 해금 |
| 스테이지 4 ~ 5 | 3슬롯 | 스테이지 3 클리어로 해금 |

- 해금 조건은 스테이지 클리어(안), 재화 소모, 계정 레벨 중에서 정한다. (미정)
- 슬롯이 열려도 채울 히어로가 없으면 의미가 없으므로, 첫 스테이지 클리어 보상으로 뽑기 재화를 준다. (안)

### 1인 구간의 서포터 규칙 (안)

- 서포터의 "스쿼드 전체" 효과는 **자기 자신도 포함**한다. (혼자여도 공속·치명타·최대 체력 버프가 의미 있다.)
- "다른 히어로"를 대상으로 하는 효과(마력 충전병, 세라피나의 궁극기 게이지 가속)는 혼자일 때 효과가 없다. 이 히어로들은 1단계에서 이미 제외했다.
- 1단계 20종은 모두 혼자서도 효과가 있는지 M3 전에 확인한다.

## 3-2. 픽셀아트 방향 (안)

- 프로젝트는 **2D 픽셀아트**로 진행한다. (결정)
- 캐릭터 스프라이트 크기(예: 32×32 또는 48×48)와 타일 크기(예: 16×16)를 하나로 통일한다. (미정, 나중에 바꾸면 전부 다시 그려야 한다.)
- Unity 설정: 스프라이트는 Filter Mode를 Point(no filter), 압축을 None으로 하고 Pixel Perfect Camera를 사용한다.
- 필요한 애니메이션(안): 대기, 공격, 스킬(개별 제작 10종 중 스킬이 있는 히어로), 피격(선택). 통합 HP 구조라 히어로 사망 애니메이션은 필요 없다.
- 모듈형 파츠(일반·고급): 3D의 Bone 소켓 대신, **베이스 바디 4종의 프레임을 공유**하고 무기·머리 장식 스프라이트를 프레임마다 정해진 위치(앵커)에 붙이는 방식을 쓴다. 색상 변화는 팔레트 스왑(색상 교체)으로 처리한다. (안)
- 원본 작업 파일(예: .aseprite)은 바이너리라 Git에서 자동 병합이 안 된다. 같은 파일은 한 사람만 수정한다.
- 에셋 스토어 픽셀 에셋을 쓰는 경우, 저장소가 Public이라면 라이선스를 반드시 확인한다.

## 4. 가챠 1단계 규칙 (안)

- 뽑기 풀은 위 20종이다. 신화가 없으므로 신화 확률(0.2%)을 전설에 더한다.

| 등급 | 확률 | 풀 수량 | 종당 확률 |
|---|---|---|---|
| 일반 | 45% | 6종 | 7.5% |
| 고급 | 30% | 4종 | 7.5% |
| 희귀 | 15% | 4종 | 3.75% |
| 영웅 | 8% | 4종 | 2% |
| 전설 | 2% | 2종 | 1% |

- 재화는 **뽑기 재화 한 종류**만 쓴다. 획득처는 스테이지 클리어 보상 (안).
- 천장과 10회 보장 규칙은 gacha.md의 안을 따른다. 수치는 미정.
- 기본 히어로: 시작 시 **1종**을 제공한다. (결정) 어떤 히어로로 할지는 미정이다. 혼자서도 이해하기 쉬운 근접 탱커형(징집병 등)이나 원거리 딜러형(수습 궁수 등)이 후보다.

## 8. 시작 전에 확정해야 할 사항

1. ~~2D인가 3D인가~~ → **2D 픽셀아트로 결정.** 다음으로 캐릭터 해상도와 타일 크기를 정한다.
2. **히어로와 디펜스(타워)의 관계**: 전투 시스템 전체가 달라진다.
3. **조작 방식**: 자동 전투 + 스킬 자동 발동(이 문서의 전제)이 맞는지 확인한다.
4. **스쿼드 통합 HP** 구조 확정, 히어로 사망 개념이 없는 것도 확정한다.
5. **기본 히어로**: 1종으로 시작하는 것은 결정됨. 어떤 히어로로 제공할지 정한다.
6. **적과 웨이브 명세**: 5절의 임시 규모를 대체할 명세가 필요하다.
7. **상태이상 3종(기절·넉백·슬로우)의 규칙**: 보스에게 통하는지, 중첩되는지를 짧게 정한다.
8. **호크아이의 이름**: 마블 캐릭터와 겹치므로 바꾸는 것을 권장한다.
